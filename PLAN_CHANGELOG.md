## Phase 2.2 — Trace Exporter & Simulation Instrumentation Adaptations (2026-11-14)
- **Boundary Projection for Unbounded `UAV.move()`**: `UAV.move(cfg)` advances `position = position + velocity * timeStep` without reflective or periodic bounds so `Predictor.predict` and `Residual` match linearly. Rather than mutating `UAV.m` physics, `TraceExporter.projectPosition(pos, areaX, areaY)` applies continuous specular reflection into `[0, areaX] x [0, areaY]` strictly at JSON serialization time.
- **Explicit Triggering `clusterID` for `FlatSBP` & Departure Capture**: `FlatSBP.m` returns `RekeyResult` with `clusterID = []`, and `protocol.leave`/`failure` removes the departing node before metrics logging. `Simulation.m` therefore captures `triggerClusterID` prior to protocol execution and passes it explicitly into `TraceExporter.buildTraceRecord(...)` so bounded `nodePositions` scoping (`<= clusterSize + 1`) and `clusterMembershipAfter` remain well-defined across all protocols.
- **Paired DT Physical Instability Under `cfg.enableTraceExport`**: `Simulation.schedulePredictedDepartures()` normally returns early when `~isa(obj.protocol, "DTHSBP")`, leaving reactive protocols with `0` DT-driven instability leaves. When `cfg.enableTraceExport == true`, `schedulePredictedDepartures()` isolates hazard draws with a deterministic per-step RNG stream, schedules `DTPredictedDepartureEvent` identically across all five protocols, and calls `uav.dt.cancelPrediction()` for non-`DTHSBP` protocols so `DTHSBP` batches predicted leaves while reactive protocols handle each physical departure individually at the exact same timestamp. When `cfg.enableTraceExport` is absent or `false`, baseline behavior is bit-for-bit unchanged.
